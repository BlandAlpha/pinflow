## 修复开机自动启动（勾选后回读仍是未勾选）

- 根因：`app.getLoginItemSettings()` 默认用空 `args` 与注册表命令比对；写入时带了 `--startup`，
  读取不带 → `openAtLogin` 恒为 false。已用探针脚本验证：`get({args:['--startup']})=true`，`get()=false`。
- 改造：新增 `electron/main/autolaunch.ts`，macOS/Linux 用 `electron-auto-launch`（跨平台选型），
  Windows 先试该库再回退 Electron 原生接口。
  - 关键坑：`electron-auto-launch@5.0.7` 在 64 位 Windows 写 `HKLM\Software\Wow6432Node\...\Run`（需管理员），
    实测本机非管理员写入被拒（探针里表现为 spawn EPERM，实际是 HKLM 拒绝访问）。
  - 库写成功时清掉原生项，避免登录启动两次；关闭时无条件清原生项。
- 兼容参数：主窗口静默启动同时识别 `--startup`（原生写入）与 `--hidden`（库 isHidden 在 mac/linux 写入）。
- 设置弹窗改用主进程返回的真实状态，写失败自动回滚。
- 新增 `tests/autolaunch.test.ts`（mock electron + 库）覆盖：库失败回退、关闭清理、库成功去双开。3 例通过。

## 追加：开机弹出 Electron 欢迎页

- 现象：开机启动弹出 Electron 默认欢迎页（标题栏 Electron，提示 `electron.exe path-to-app`）。
- 原因：注册表 `HKCU\...\Run\electron.app.Electron = ...\node_modules\electron\dist\electron.exe --startup`
  —— 开发态（`electron .` / electron-vite dev）勾选开机自启时写的项，命令里没有应用目录，
  electron.exe 不知道自己该跑哪个 app，只显示欢迎页。
- 处理：
  1. 已删除该遗留注册表项（保留正常项 `electron.app.todo-tracker` → forge-dist 的 exe）。
  2. `autolaunch.ts` 增加开发态分支：`!app.isPackaged` 时不用 electron-auto-launch
     （库只写 process.execPath，同样缺应用目录），改用原生接口并写 `args = [app.getAppPath(), '--startup']`。
- 提交：029f593

## 商业化迭代流程：远程仓库 / CI 自动构建 / 分发 / 应用内更新

用户目标：接入商业产品化流程——远程仓库按 tag 管理版本、CI 自动 Build、托管分发平台、
软件内自带升级检测与应用内升级。

选型（用户已确认）：GitHub 私有仓库 + GitHub Actions + **Cloudflare R2（绑自定义域名）** +
electron-updater（generic provider）+ 暂不代码签名。

- **不把 Release 放私有仓库**的原因：私有仓库的 Release 资产下载需认证，客户端必须内置
  token（可被逆向提取），等于泄露代码库只读权限；且 GitHub 下载在国内慢。
- 免费方案实情（已查证 2026-08 额度）：R2 有 10GB 存储 + **出站流量永久免费无限**，
  不需备案域名；七牛云只有 10GB/月且**仅 HTTP CDN 流量免费（HTTPS 收费）**，还需备案域名。
  故选 R2。开通 R2 需绑卡（不超额不扣费）。

实现（本轮新增）：
- `electron/main/updater.ts`：更新状态机（idle/checking/available/not-available/downloading/
  downloaded/error）+ electron-updater 装配。`autoDownload=false`（用户点「下载更新」才下）、
  `autoInstallOnAppQuit=true`（下载完直接退出也顺手装）。启动后延迟 8s 静默检查一次。
- 可用性判定 = `app.isPackaged && existsSync(process.resourcesPath/app-update.yml)`。
  免安装版（`npm run package`）**没有** app-update.yml（只有 make 出的安装包里有），
  所以也标记为不可用——避免用户点按钮收到 ENOENT。
- `forge.config.js` nsis maker 新增 `updater: { url, name, channel, updaterCacheDirName }`：
  该 maker 会自动写包内 `resources/app-update.yml`（provider: generic）与安装包旁 `latest.yml`。
  **刻意不设 publisherName**——设了 electron-updater 会强制校验代码签名。
- `artifactName: 'todo-tracker-${version}-setup.${ext}'`：去掉空格，URL 更安全。
- `UPDATE_BASE_URL` 环境变量（默认占位 `https://dl.example.com/todo-tracker`）注入更新源地址；
  写进包内 app-update.yml，换 CDN 必须重新发版。
- 新增 `.github/workflows/release.yml`：tag `v*` 或手动触发 → 校验 tag 与 package.json 版本一致 →
  typecheck/test → `node scripts/fetch-native.mjs`（换 Electron ABI）→ make → 先传 exe/blockmap
  再传 latest.yml（顺序反了老客户端会 404）→ 存档 Artifacts → 建 GitHub Release。
  R2 secrets 未配置时跳过上传并告警（先验证链路）。aws-cli 需
  `AWS_REQUEST_CHECKSUM_CALCULATION=when_required`，否则 R2 不认新版校验头报 400。
- `package.json` 加 `release:patch/minor/major`（`npm version` 自动改版本+提交+打 tag）。
- 新增 `docs/RELEASE.md`（版本规则、R2 首次配置、GitHub 变量/密钥清单、日常发版、排障表）与
  README 的「应用内更新与版本发布」段落。
- 新增 `tests/updater.test.ts`（10 例，mock electron + electron-updater + node:fs）：
  开发态/免安装版不可用、available/not-available 流转、下载进度、重复点下载去重、
  未下载不允许安装且 quitAndInstall 用 (true,true) 静默、网络错误转人话、托盘通知。

其它：
- `forge.config.js` 的 `outDir` 支持 `FORGE_OUT_DIR` 覆盖：Windows 上 forge-dist 里的
  app.asar 常被 Defender/索引占用，Forge 清目录会报「另一个进程正在使用此文件」，
  本地验证时换空目录即可，不必动已发布产物。
- 用户确认方向后新增 git 提交：见 docs/RELEASE.md 引用的提交。
